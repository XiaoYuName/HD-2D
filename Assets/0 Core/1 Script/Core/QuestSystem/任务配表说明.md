# 任务配表说明（给策划）

面向配表的速查手册。三张表：**任务表** `QuestDataConfig.xlsx` ／ **任务目标表** `QuestObjConfig.xlsx` ／ **任务类别表** `QuestCategoryData.xlsx`，都在 `ExcelTool/LubanTools/DataTables/Datas/` 下。改完必须跑一次 `DataTables/gen_client.bat` 才会生效。

---

## 0. 通用写法：位置参数

领取方式、任务目标、奖励这三类列全部用同一套写法：

```
类型:参数1:参数2      多条之间用 / 分隔
```

例：`DayPassed:2`、`Coin:100/Affection:10001:10`、`CompleteGame:1001:2:1`

| 符号 | 含义 |
| --- | --- |
| `:` | 同一条里的参数分隔 |
| `/` | 多条之间的分隔（一列里配多条） |
| `+` | **仅**用于「任务目标ID列表」「任务ID列表」这种纯 ID 列（Luban 的 list 分隔符） |
| `[ ]` | 本文档里表示该参数可省略，**表里不要真的写方括号** |

参数按位置认，不能跳着写：想填第 3 个参数就必须把第 2 个也填上。列留空 = 不配这一项。

**写错会在游戏启动时报错**，Console 里会打出是哪张表哪一行、原文是什么、正确写法是什么，照着改即可。

## 1. 任务表 QuestDataConfig.xlsx

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `Id` | long | 任务ID，全表唯一 |
| `Remark` | string | 备注，只给人看 |
| `QuestTrigger` | string | 领取方式，见 §1.1。多条之间是 **或**（任一命中就领）；留空 = 只看 `AcceptCond` |
| `AcceptCond` | long | 领取条件ID，走条件系统（Cond 表）。留空/0 = 无条件 |
| `NameKey` | string | 任务名的多语言 Key |
| `DescKey` | string | 任务描述的多语言 Key |
| `IconKey` | string | 任务图标 |
| `QuestObjData` | list, long | 本任务的目标，填**任务目标表的 Id**，多条用 `+`：`10001+10002` |
| `Reward` | string | 任务整体完成时发的奖励，见 §3 |
| `ObjInOrder` | bool | `True` = 目标必须按上面的顺序一条条完成 |

**示例行**

| Id | Remark | QuestTrigger | AcceptCond | NameKey | QuestObjData | Reward | ObjInOrder |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 10001 | 测试任务1 | `EnterZone:10000:10001` | 10002 | TestQuest1Name | `10001+10002` | `Coin:100/Affection:10001:10` | False |
| 10004 | 测试任务4 | `EnterZoneStay:10000:10001:5` | 10006 | TestQuest4Name | `10002+10005` | `Coin:100` | False |

> **`ObjInOrder` 什么时候必须填 True**：目标里有「持有道具」「好感度达到多少」这类**看当前状态**的目标时，如果玩家身上本来就有那件道具，任务一领就算这条目标已完成、直接发奖。要求「先做A再做B」就把它设成 True——顺序模式下同一时刻只有当前那条目标在生效。

### 1.1 领取方式 QuestTrigger

| 写法 | 什么时候触发 |
| --- | --- |
| （留空） | 不看触发，只要 `AcceptCond` 满足就自动领 |
| `Auto` | 条件满足即领，同上但显式写出来 |
| `EnterZone:大场景ID` | 进入某个大场景（从大地图进它下面任一小场景时算） |
| `EnterZone:大场景ID:小场景ID` | 进入某个小场景 |
| `ExitZone:大场景ID[:小场景ID]` | 离开某个大场景 / 小场景，写法同上 |
| `EnterZoneStay:大场景ID:小场景ID:秒数` | 停留够秒数，小场景写 `0` = 在整个大场景里累计 |
| `ClickNpc:NPC ID` | 点击某个 NPC |
| `DialogNpc:NPC ID` | 和某个 NPC 对话结束 |
| `MiniGameEnd:小游戏类型` | 某个小游戏结束（不看输赢），类型见 §2.3 |
| `MiniGameResult:小游戏类型:结果` | 小游戏结束且结果匹配，结果写 `Win` 胜 / `Lose` 负 |
| `RandomChance:千分比` | 每次重扫时按概率命中，`RandomChance:50` = 5% |
| `PlotEnd:剧情ID` | 某段剧情播完 |

多条用 `/` 连：`EnterZone:10000:10001/ClickNpc:10001` = 进 10001 号小场景**或**点了 10001 号 NPC 都能领。

> **场景ID 是两级的**：大场景ID 查 `WordMapSceneData.xlsx`（家 10000、商业街 10001…），小场景ID 查
> `GameSceneData.xlsx`（公寓卧室 10001、女主卧室 10002…）。两张表的 ID 区间**重叠**，所以区域触发一律
> 先写大场景、再写小场景，只写一个 ID 会被当成大场景。小场景必须在对应大场景的 `SubScenes` 里，
> 写错启动时会直接报错。
>
> 只写大场景的那种，**在这个大场景里换小场景不会重复触发**（进大场景算一次、退出大场景算一次）。

### 1.2 领取条件 AcceptCond（QuestStoryCondData.xlsx）

一行里各列之间是 **AND**：全部满足才算通过。列的写法：

| 列 | 写法 | 说明 |
| --- | --- | --- |
| `ItemOwn` | `道具ID+数量`，多条用 `/` | 背包里持有够数量 |
| `NpcProp` | `角色ID+属性+数值`，多条用 `/` | 属性写 `Goodwill` 好感 / `GoodwillLevel` 好感等级 |
| `PlotPre` | 剧情ID，多条用 `+` | ⏳ 剧情完成记录未实现，**填了就永远不满足** |
| `DlgPre` | 对话ID，多条用 `+` | 这些对话都播过 |
| `Day` | 数字 | 第几天起，`0` = 不限 |
| `TimeSlot` | `All` / `Morning` / `Noon` / `Evening` / `Midnight` | 时间段，不限就填 `All`（这列不能留空） |
| `QuestPre` | 任务ID，多条用 `+` | 这些任务都已完成 |
| `Satisfy` / `NotSatisfy` / `GameScore` | — | ⏳ 未实现，读都不读，别填 |

表里现成的测试行，**每种条件各一条**，测哪一项就把任务的 `AcceptCond` 指过去：

| Id | 测什么 |
| --- | --- |
| 10001 | 多项 AND（道具 ＋ 好感 ＋ 两段对话 ＋ 第2天） |
| 10002 | **无门槛**，只想验证触发本身就用它 |
| 10003 | 道具持有（100001 ×1） |
| 10004 | NPC 好感（10001 好感 ≥10） |
| 10005 | 对话前置（10100 播过） |
| 10006 | 天数达到（第2天起） |
| 10007 | 时间段（黄昏） |
| 10008 | 前置任务（10001 已完成） |
| 10009 | 剧情前置 —— 用来确认「未实现的条件不会误判通过」，永远领不到 |

现在 5 条测试任务的挂法：10001→10002（空，跑通流程用）、10002→10003（道具）、10003→10004（好感）、10004→10006（天数）、10005→10005（对话）。10007 / 10008 / 10009 没有任务引用，要测就临时改某条任务的 `AcceptCond`。

## 2. 任务目标表 QuestObjConfig.xlsx

一行 = **一条目标 ＋ 它的奖励 ＋ 可选的超额目标和超额奖励**。同一行可以被多个任务引用。

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `Id` | long | 目标ID，任务表的 `QuestObjData` 填的就是它 |
| `Remark` | string | 备注 |
| `DescKey` | string | **必填**，界面上这条目标显示的文字，多语言 Key。不填界面上就是一行空白（启动会报错提醒） |
| `QuestObjData` | string | 目标本体，见 §2.1 |
| `Reward` | string | 这条目标完成时发的奖励，见 §3 |
| `ExtraDescKey` | string | 超额目标的描述 Key，配了超额就必填 |
| `ExtraCompleteCond` | string | 超额目标，写法和 `QuestObjData` 完全一样，留空 = 不配 |
| `ExtraReward` | string | 超额目标也达成时**追加**发的奖励 |

**示例行**

| Id | DescKey | QuestObjData | Reward | ExtraDescKey | ExtraCompleteCond | ExtraReward |
| --- | --- | --- | --- | --- | --- | --- |
| 10001 | TestObj1Desc | `DayPassed:2` | `Coin:100/Affection:10001:10` | TestObj1ExtraDesc | `CompleteGame:CrashSprint:2:Win` | `Coin:100` |
| 10005 | TestObj5Desc | `BuyItem:100001:1` | `Coin:100` | | | |

> 超额目标在界面上**单独成块**排在目标列表下面，标题是「超额奖励」，行首写「任务N」指回它属于第几条目标。超额只在**主目标完成的那一刻**结算：主目标完成时超额也满足才发超额奖，之后再补做没用。

### 2.1 目标类型一览

| 写法 | 含义 | 族 |
| --- | --- | --- |
| `DayPassed:天数` | 游戏进行到第 N 天 | 计量 |
| `HoldItem:道具ID[:数量]` | 身上持有某道具 N 个，数量不写默认 1 | 计量 |
| `CharacterProp:NPC ID:数值[:属性类型]` | 某 NPC 的属性达到 N，属性不写默认好感值 | 计量 |
| `Dialog:对话ID` | 完成某段指定对话 | 状态 |
| `CompleteQuest:任务ID` | 完成另一个任务 | 状态 |
| `CompleteGame:小游戏类型:局数[:结果]` | 玩 N 局小游戏，类型见 §2.3；结果不写＝不限胜负，也可写 `Win` / `Lose` | 累计 |
| `DialogNpc:NPC ID[:次数]` | 和某 NPC 对话 N 次，不写默认 1 | 累计 |
| `DialogNpcWithItem:NPC ID:道具ID[:次数]` | 带着某道具找 NPC 对话 N 次，**每次消耗 1 个**；道具不够那次不算 | 累计 |
| `GiveGift:NPC ID:礼物ID[:次数]` | 送礼 N 次，礼物ID 填 `0` = 任意礼物 | 累计 |
| `BuyItem:道具ID[:件数]` | 购买某道具 N 件，道具ID 填 `0` = 任意道具 | 累计 |

`CharacterProp` 的属性类型：`Feeling` 心情值 / `Goodwill` 好感值（默认）/ `GoodwillLevel` 好感等级。写枚举名或数字都行。

**三个「族」的区别（影响进度会不会倒退）**

| 族 | 进度怎么算 | 会不会倒退 | 领任务前就满足算不算 |
| --- | --- | --- | --- |
| 计量 | 每次现查当前的量（背包里几个、第几天） | **完成前会**。卖掉道具、好感掉了，进度跟着退回去 | 算，一领就完成 |
| 状态 | 现查有没有发生过 | 不会 | 算，一领就完成 |
| 累计 | 领任务后自己数次数，存进存档 | 不会，只增不减 | **不算**，只数领任务之后的 |

目标一旦完成就地发奖并定格，之后再把道具卖了也不会退回未完成、更不会收回奖励。

想要「必须领了任务之后再去做」，就别用计量/状态族，或者给任务打开 `ObjInOrder`。

### 2.2 描述文本怎么写

`DescKey` 指向的多语言文本里可以插占位符，运行时自动替换：

| 占位符 | 替换成 | 哪些目标能用 |
| --- | --- | --- |
| `{Value}` | 目标要求的数量/数值 | 计量族、累计族 |
| `{Progress}` | 当前进度，形如 `1/2` | 计量族、累计族 |
| `{ItemName}` | 道具名 | HoldItem / DialogNpcWithItem / GiveGift / BuyItem |
| `{CharacterName}` | NPC 名 | CharacterProp / DialogNpc / DialogNpcWithItem / GiveGift |
| `{QuestName}` | 任务名 | CompleteQuest |
| `{PropName}` | 属性名（好感值/心情值…） | CharacterProp |

例：`DayPassed:2` 配文案「先在小镇安顿下来，住满 {Value} 天（{Progress}）」→ 界面显示「先在小镇安顿下来，住满 2 天（1/2）」。

状态族（`Dialog`/`CompleteQuest`）没有进度概念，别在它们的文案里写 `{Progress}`。

文案写在 `Assets/0 Core/1 Script/Data/QuestSystem/QuestDataLoc.csv`。`QuestObj/*` 那批是各类型的通用说法，直接把 Key 填进 `DescKey` 就能用；要单独写一句就自己起个新 Key。

### 2.3 小游戏类型一览

`CompleteGame` / `MiniGameEnd` / `MiniGameResult` 的「小游戏类型」**写下表里的名字**（不是数字、不是面板名）。
这批名字来自 `__enums__.xlsx` 的 `MiniGameType` 枚举，写错启动就报错。

| 写法 | 小游戏 | 什么算胜 |
| --- | --- | --- |
| `CrashSprint` | 赌场·暴走冲刺 | 爆点前收手 |
| `WitchPotion` | 赌场·女巫毒药 | 没开到毒药就收手 |
| `Fishing` | 钓鱼 | 遛鱼成功、鱼上钩 |
| `Cooking` | 料理 | 做菜成功 |
| `SprayPaint` | 服装·喷漆 | 通关 |
| `Embroidery` | 服装·刺绣填色 | 通关 |
| `ShopHelp` | 超市帮忙上货 | 时间内摆满 |
| `FactoryProcess` | 加工厂·下压加工 | 本局有产出 |
| `FactoryMold` | 加工厂·物料制作 | **不分胜负**，别配 `Win`/`Lose` |
| `PhotoStudio` | 摄影棚·对焦 | 对焦达标 |

> 「一局结束」算在结算结果定下来那一刻，玩家看不看结算面板都算。漫画室的绘制流程不是一局一局的小游戏，
> 没有对应类型，配不了。新小游戏要能被任务统计，找程序在枚举里补一项。

## 3. 奖励怎么配

任务表 `Reward`、目标表 `Reward`/`ExtraReward`、类别表 `Reward` 四处写法完全一样：

| 写法 | 含义 |
| --- | --- |
| `Item:道具ID[:数量]` | 发道具，数量不写默认 1 |
| `Coin:数值` | 金钱 |
| `GameCoin:数值` | 游戏币（赌场那套独立货币） |
| `Affection:NPC ID:数值` | 某 NPC 好感度 |

多条用 `/` 连：`Coin:100/Affection:10001:10/Item:100001:2`

发奖时会弹「获得奖励」窗。同一时刻发好几份（最后一条目标完成 + 任务完成 + 类别完成）会排队一份份点过去，不会互相顶掉。

## 4. 任务类别表 QuestCategoryData.xlsx

面板左侧一个 Tab 就是一个类别。

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `Id` | long | 类别ID |
| `Remark` | string | 备注 |
| `NameKey` / `DescKey` / `IconKey` | string | 名称/描述/图标 |
| `QuestId` | list, long | 归到这个类别下的任务，多条用 `+`：`10001+10002+10003` |
| `Reward` | string | 类别下**所有任务**都完成时发一次的奖励，只发一次 |

**示例行**

| Id | NameKey | QuestId | Reward |
| --- | --- | --- | --- |
| 10001 | QuestCategory1Name | `10001+10002+10003` | `Coin:100/Affection:10001:10` |

> 一个任务可以同时挂在多个类别下。面板上**只显示已经接到过任务的类别**，一个任务都没接的类别不会出现。

## 5. 常见问题

| 现象 | 原因 |
| --- | --- |
| 启动报「类型 XXX 还没注册实现」 | 类型名拼错了，或这个类型还没做，对照 §1.1/§2.1 |
| 启动报「参数不够」 | 少填了必填参数，报错里会给正确写法 |
| 启动报「不是合法的 MiniGameType / 小游戏类型没填」 | 小游戏名写错或写成了数字，对照 §2.3 |
| 启动报「没配 DescKey」 | 目标表 `DescKey`/`ExtraDescKey` 留空了 |
| 界面上目标文字里出现 `{Value}` 没被替换 | 这个占位符该类型不支持，见 §2.2 |
| 任务一领就直接完成 | 目标是计量/状态族且当前已经满足，见 §2.1 |
| 类别 Tab 不显示 | 该类别下一个任务都没接到 |
| 改了表没生效 | 忘了跑 `DataTables/gen_client.bat` |
