# 任务配置说明（给策划）

任务不再配 Excel。全部配置在一个资产里：**`Assets/Resources/Quest/QuestDatabase.asset`**，
用 **`Tools/任务编辑器`** 打开窗口来改（左边选表和记录、右边填字段），改完点工具栏的 **校验** 和 **保存**。
操作细节见 `任务编辑器说明.md`。

资产里五个字典，每个字典的 Key 就是 ID：

| 字典 | 一条是什么 |
| --- | --- |
| 任务 | 一个任务：领取触发、接受条件、名称描述图标、目标ID列表、任务奖励 |
| 任务目标 | 一条目标 ＋ 它的奖励 ＋ 可选的超额目标和超额奖励（可被多个任务共用） |
| 任务类别 | 面板左侧一个页签：归到它下面的任务ID列表 ＋ 类别奖励 |
| 接受条件 | 一组状态门槛，各项之间是 AND |
| 奖励显示 | 一种奖励类型在 UI 上的图标和名字（道具奖励不用配，图标在道具表里） |

**三层都能配奖励**：目标完成发目标奖励，任务全达成发任务奖励，类别下所有任务完成再发一次类别奖励。

---

## 0. 通用：选类型，再填这个类型的参数

领取触发、任务目标、奖励都是「先在下拉里选类型，下面只出现这个类型需要的字段」。
没有位置参数、没有 `类型:参数:参数` 这种字符串了，也不存在参数写少了、顺序写反了这种错。

ID 类字段（道具 / NPC / 对话 / 场景 / 任务 / 目标 / 条件）都是可搜索的 `ID | 备注` 选择器，不用手记数字。
多语言字段是 Key 选择器，带简体中文预览。
写着「0=任意」「0=不限」的字段选第一项「无 / 不限」即可。

## 1. 任务

| 字段 | 说明 |
| --- | --- |
| 备注 | 只给人看 |
| 名称 / 描述 / 图标 | 多语言引用（Key 以 `Quest/` 开头）＋ Addressables 图标 |
| 领取触发 | 多条之间是**或**（任一命中就尝试领）；**留空 = 只看接受条件** |
| 接受条件 | 选一条条件；选「无」= 无门槛 |
| 任务目标（按顺序） | 本任务的目标ID列表 |
| 任务奖励 | 全部目标达成、自动交付时发 |
| 目标按顺序完成 | 打开 = 必须按上面列表的顺序一条条做 |

> **「目标按顺序完成」什么时候必须打开**：目标里有「持有道具」「好感达到多少」这类看**当前状态**的目标时，
> 玩家身上本来就有那件道具的话，任务一领就算这条完成、直接发奖。要求「先做A再做B」就打开它 ——
> 顺序模式下同一时刻只有当前那条目标在生效。

### 1.1 领取触发类型

| 类型 | 什么时候触发 |
| --- | --- |
| `AutoQuestTrigger` | 被动：读档、天数变化、对话结束、任务完成后重扫一遍，只看接受条件（不配触发等同于此） |
| `EnterZoneQuestTrigger` | 进入某场景 |
| `ExitZoneQuestTrigger` | 离开某场景 |
| `EnterZoneStayQuestTrigger` | 在某场景停够若干秒 |
| `ClickNpcQuestTrigger` | 点击某 NPC |
| `DialogNpcQuestTrigger` | 和某 NPC 对话结束 |
| `MiniGameEndQuestTrigger` | 某小游戏结束（不看输赢） |
| `MiniGameResultQuestTrigger` | 某小游戏结束且结果匹配（结果选 `None` = 不限） |
| `RandomChanceQuestTrigger` | 每次重扫按千分比掷点 |
| `PlotEndQuestTrigger` | 某段剧情播完 —— ⏳ 剧情完成记录未实现，**永不命中** |

> **场景是两级的**：大场景（家、商业街…）和小场景（公寓卧室、女主卧室…）两张表的 ID 区间**重叠**，
> 所以区域触发要同时选大场景和小场景；小场景选「不限」= 只认大场景本身
> （进大场景算一次、退出算一次，在里面换小场景不重复触发）。小场景必须属于所选的大场景，选错启动时报错。

「NPC 数值达标」「第几天」「任务已完成」这类**状态**不做成触发，写进接受条件。

### 1.2 接受条件

一条条件里各项之间是 **AND**，全部满足才通过：

| 字段 | 说明 |
| --- | --- |
| 道具持有要求 | 道具 ＋ 数量，背包里够数 |
| 角色属性要求 | NPC ＋ 属性（心情值 / 好感值 / 好感等级）＋ 数值 |
| 前置剧情 | ⏳ 剧情完成记录未实现，**填了就永远不满足** |
| 前置对话 | 这些对话都播过 |
| 最早天数 | 第几天起，0 = 不限 |
| 时间段 | `All` = 不限，其余按时段 |
| 前置任务 | 这些任务都已完成 |
| 满足时分支 / 不满足时分支 / 游戏分数 | ⏳ 未实现，任务系统不读 |

## 2. 任务目标

一条 = **主目标 ＋ 目标奖励 ＋ 可选的超额目标和超额奖励**。描述文案填在目标类型自己的「目标描述」字段里。

超额目标不配就是没有。超额只在**主目标完成的那一刻**结算：那一刻超额也满足才发超额奖励，之后补做没用。
界面上超额单独成块排在目标列表下面，行首写「目标N」指回它属于第几条。

### 2.1 目标类型一览

| 类型 | 含义 | 族 |
| --- | --- | --- |
| `DayPassedObjData` | 游戏进行到第 N 天 | 计量 |
| `HoldItemObjData` | 身上持有某道具 N 个 | 计量 |
| `CharacterPropObjData` | 某 NPC 的属性达到 N | 计量 |
| `DialogObjData` | 完成某段指定对话 | 状态 |
| `CompleteQuestObjData` | 完成另一个任务 | 状态 |
| `CompleteGameObjData` | 玩 N 局某小游戏，可限定胜负（`None` = 不限） | 累计 |
| `DialogNpcObjData` | 和某 NPC 对话 N 次 | 累计 |
| `DialogNpcWithItemObjData` | 带着某道具找 NPC 对话 N 次，**每次消耗 1 个**；道具不够那次不算 | 累计 |
| `GiveGiftObjData` | 送礼 N 次（礼物选「任意」= 不限品类） | 累计 |
| `BuyItemObjData` | 购买某道具 N 件（道具选「任意」= 不限品类） | 累计 |

**三个「族」的区别（影响进度会不会倒退）**

| 族 | 进度怎么算 | 会不会倒退 | 领任务前就满足算不算 |
| --- | --- | --- | --- |
| 计量 | 每次现查当前的量（背包里几个、第几天） | **完成前会**。卖掉道具、好感掉了，进度跟着退回去 | 算，一领就完成 |
| 状态 | 现查有没有发生过 | 不会 | 算，一领就完成 |
| 累计 | 领任务后自己数次数，存进存档 | 不会，只增不减 | **不算**，只数领任务之后的 |

目标一旦完成就地发奖并定格，之后再把道具卖了也不会退回未完成、更不会收回奖励。
想要「必须领了任务之后再去做」，就别用计量/状态族，或者给任务打开「目标按顺序完成」。

一条目标只做一件事：「1 条鱼 + 2 颗糖」写成两条 `HoldItemObjData`；「和 A、B 都对话」写成两条 `DialogNpcObjData`
（同一任务下的多条目标之间本来就是 AND）。

### 2.2 描述文本怎么写

目标描述里可以插占位符，运行时自动替换：

| 占位符 | 替换成 | 哪些目标能用 |
| --- | --- | --- |
| `{Value}` | 目标要求的数量/数值 | 计量族、累计族 |
| `{Progress}` | 当前进度，形如 `1/2` | 计量族、累计族 |
| `{ItemName}` | 道具名 | HoldItem / DialogNpcWithItem / GiveGift / BuyItem |
| `{CharacterName}` | NPC 名 | CharacterProp / DialogNpc / DialogNpcWithItem / GiveGift |
| `{QuestName}` | 任务名 | CompleteQuest |
| `{PropName}` | 属性名（好感值/心情值…） | CharacterProp |

例：`DayPassedObjData` 需要天数 2，文案「先在小镇安顿下来，住满 {Value} 天（{Progress}）」
→ 界面显示「先在小镇安顿下来，住满 2 天（1/2）」。

状态族（Dialog / CompleteQuest）没有进度概念，别在它们的文案里写 `{Progress}`。
文案写在 `Assets/0 Core/1 Script/Data/QuestSystem/QuestDataLoc.csv`，`QuestObj/*` 那批是各类型的通用说法，
直接引用就能用；要单独写一句就自己起个新 Key（前缀 `QuestObj/`）。

### 2.3 小游戏类型一览

| 枚举 | 小游戏 | 什么算胜 |
| --- | --- | --- |
| `CrashSprint` | 赌场·暴走冲刺 | 爆点前收手 |
| `WitchPotion` | 赌场·女巫毒药 | 没开到毒药就收手 |
| `Fishing` | 钓鱼 | 遛鱼成功、鱼上钩 |
| `Cooking` | 料理 | 做菜成功 |
| `SprayPaint` | 服装·喷漆 | 通关 |
| `Embroidery` | 服装·刺绣填色 | 通关 |
| `ShopHelp` | 超市帮忙上货 | 时间内摆满 |
| `FactoryProcess` | 加工厂·下压加工 | 本局有产出 |
| `FactoryMold` | 加工厂·物料制作 | **不分胜负**，别限定 Win/Lose |
| `PhotoStudio` | 摄影棚·对焦 | 对焦达标 |

> 「一局结束」算在结算结果定下来那一刻，玩家看不看结算面板都算。漫画室的绘制流程不是一局一局的小游戏，
> 没有对应类型，配不了。新小游戏要能被任务统计，找程序在枚举里补一项。

## 3. 奖励

任务奖励、目标奖励、超额奖励、类别奖励四处的选项完全一样：

| 类型 | 含义 |
| --- | --- |
| `ItemQuestReward` | 发道具（道具 ＋ 数量） |
| `CoinQuestReward` | 金钱 |
| `GameCoinQuestReward` | 游戏币（赌场那套独立货币） |
| `AffectionQuestReward` | 某 NPC 好感度 |

除道具以外的类型，都要在「奖励显示」字典里配好图标和名字，不然界面上只有类型名、没有图标（校验会报）。

发奖时会弹「获得奖励」窗。同一时刻发好几份（最后一条目标完成 + 任务完成 + 类别完成）会排队一份份点过去，不会互相顶掉。

---

## 4. 任务类别

面板左侧一个页签就是一个类别：名称 / 描述 / 图标 ＋ 任务列表 ＋ 类别奖励（该类别下所有任务都完成时发一次）。

一个任务可以同时挂在多个类别下。面板上**只显示已经接到过任务的类别**，一个任务都没接的类别不会出现；
类别打开后，里面还没领的任务也会灰着画出来，那是给玩家的线索。

## 5. 常见问题

| 现象 | 原因 |
| --- | --- |
| 校验报「没选主目标类型 / 奖励列表里有空项」 | 加了一条但没在下拉里选类型 |
| 校验报「引用的任务/目标/条件不存在」 | 引用的 ID 被删了或还没建 |
| 校验报「用了 XX 奖励但没配奖励显示」 | 「奖励显示」字典里缺这个类型 |
| 校验报「没配目标描述」 | 目标（或超额目标）的「目标描述」留空了 |
| 启动报「道具/角色 XXX 不存在」 | ID 指向的东西不在道具表/角色表里 |
| 启动报「小游戏类型没填」 | 小游戏枚举留在 `None` 了 |
| 界面上目标文字里出现 `{Value}` 没被替换 | 这个占位符该类型不支持，见 §2.2 |
| 任务一领就直接完成 | 目标是计量/状态族且当前已经满足，见 §2.1 |
| 类别页签不显示 | 该类别下一个任务都没接到 |
