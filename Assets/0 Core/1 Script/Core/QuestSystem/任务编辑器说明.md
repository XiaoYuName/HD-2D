# 任务编辑器与渐进迁移

## 入口与数据资产

- 编辑器入口：`Tools/任务编辑器`
- 数据资产：`Assets/Resources/Quest/QuestDatabase.asset`
- 数据类型：`QuestDatabaseData : ScriptableObject`

## 表格式配置

窗口按原 Luban 配置拆为“任务、目标、接受条件、类别、奖励显示”5 个表页签。每条记录是一行，字段是一列，可横向滚动并直接编辑：

- 目标类型使用“英文名 - 中文说明”的双语下拉框；
- 任务、目标和接受条件引用使用“ID + 备注”下拉框；
- 道具 ID 使用可按“ID + 中文名称”检索的搜索框；NPC、对话和场景引用使用 Luban JSON 生成的可读下拉选项，SO 中仍只保存数值 ID；
- 多值引用、领取触发、目标参数、奖励和复合条件在单元格显示摘要，点击后用 UI Toolkit 弹层编辑；
- 名称和描述单元格显示 `QuestSystem/Key`；点击后展示简体中文预览，只有输入 Key 或中文内容时才实时生成最多 32 条匹配结果，点击整行即可选择；图标仍使用 Addressables 字段；
- 搜索、加行、复制、删除、保存与校验都作用于当前表。
- 五个表页签分别记忆用户调整后的列宽，布局保存在 `QuestDatabaseData` 中；关闭窗口时若仍有未保存修改，Unity 会提示保存、放弃或取消关闭。

界面完全使用 UI Toolkit，视觉风格与“多语言工作台”保持一致。视觉规则集中在独立的 `QuestEditorWindow.uss`，C# 仅处理数据绑定和交互；数组弹层使用默认展开的卡片列表，不显示 Unity 默认折叠栏。

多语言 Key 按表格分组：任务使用 `Quest/`，目标与超额目标使用 `QuestObj/`，类别使用 `QuestCategory/`，奖励显示名称使用 `QuestRewardName/`。Excel 重新导入 SO 时会自动补齐对应前缀。渐进迁移期间，CSV 中旧的无前缀 Key 暂时作为 Luban 回退兼容项保留，但任务编辑器不会展示它们。

首次成功编译后，如果资产不存在，会自动从以下 5 张 Excel 创建数据资产：

- `QuestCategoryData.xlsx`
- `QuestDataConfig.xlsx`
- `QuestObjConfig.xlsx`
- `QuestRewardData.xlsx`
- `QuestStoryCondData.xlsx`

自动创建时的数据源模式固定为 `LubanOnly`，且首次导入的每条 SO 记录默认关闭，不会立即改变当前游戏行为。

## 渐进迁移模式

| 模式 | 行为 |
|---|---|
| `LubanOnly` | 只读 Luban；SO 可提前编辑、校验，不参与运行时。 |
| `PreferScriptableObject` | 每条启用的 SO 记录按 ID 覆盖 Luban；SO 缺失或停用的记录回退 Luban。 |
| `ScriptableObjectOnly` | 完全停止读取这 5 张 Luban 任务表；缺失引用视为错误。 |

每条任务、目标、条件、类别和奖励显示配置都有“启用 SO 配置”开关，因此可以按记录迁移和回滚。重新导入 Excel 会按 ID（奖励显示按类型）保留已有开关，新记录仍默认关闭。

推荐顺序：

1. 保持 `LubanOnly`，从 Excel 导入并校验。
2. 切到 `PreferScriptableObject`，先启用少量记录做游戏内验证。
3. 分批启用剩余记录；出现问题时停用对应记录即可回退 Luban。
4. 全量验证后切到 `ScriptableObjectOnly`，再从 Luban 生成清单中移除旧任务表。

## 强类型字段

SO 配置不保存 `Type:Arg/Type:Arg` 形式的业务字符串：

- 领取方式使用 `QuestTriggerSpec`，由枚举决定显示场景、NPC、小游戏、概率等字段。
- 任务目标使用 `QuestObjectiveSpec`，由枚举决定显示道具、角色、对话、次数等字段。
- 奖励使用 `QuestRewardSpec`，由枚举决定显示道具、角色和数值字段。
- 名称和描述使用 `LocalizedString`。
- 图标使用 `AssetReferenceSprite`。
- 任务、目标和条件之间继续使用稳定数值 ID，编辑器校验重复 ID 与缺失引用。

`remark` 仍是自由文本，仅用于策划备注，不参与运行时业务判定。

## Excel 导入

“重新导入 Excel”会用工作簿内容更新 SO 数据库，并保留当前数据源模式及已有记录的迁移开关。导入器直接读取 `.xlsx` 的 OpenXML 内容，不依赖 Excel 客户端或第三方 Excel DLL。

导入后应先执行“校验”。校验覆盖：

- 重复或非法 ID；
- 任务、目标、条件和类别之间的引用；
- 未选择的目标/奖励类型；
- 非正数数量与数值；
- 缺少的本地化引用、图标和奖励显示配置；
- 不符合当前表格前缀约束的多语言 Key；
- `ScriptableObjectOnly` 下禁止依赖 Luban 回退。

## 运行时兼容

现有任务事件总线、目标进度、存档结构与奖励发放逻辑不变。`QuestDataLoader` 只负责合并两种配置源，`CondManager` 对条件执行相同的 SO 优先/回退规则，因此迁移不会要求各玩法重新接入任务上报。
