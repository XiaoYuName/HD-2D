# 任务编辑器

## 入口

- 编辑器窗口：`Tools/QuestSystem - 任务系统/QuestEditor - 任务编辑器`
- 数据资产：`Assets/Resources/Quest/QuestDatabase.asset`（`QuestDatabaseData`）
- 一次性导入：`Tools/QuestSystem/从 Luban Excel 导入任务数据库（一次性）`

Luban 的 5 张任务表已经不参与运行时，任务配置只认这一个资产。

## 窗口结构

沿用原来的配表形态：顶部工具栏（数据库 / 重新导入 Excel / 校验 / 配置多语言 / 保存），
下面五个页签对应资产里的五个字典（任务 / 目标 / 接受条件 / 类别 / 奖励显示），
再下面是这张表的表格 —— **一行一条记录，一列一个字段**，配搜索框和「＋新增行 / 复制选中行 / 删除选中行」。

- 第一列就是字典 Key（ID / 奖励类型），改完失焦即换 Key，重复会拒绝并报错。
- 备注、数值、开关、枚举这些**直接在格子里改**；单个 ID 引用（接受条件）也是格子里的下拉框，不用开弹层。
- 多语言、列表、触发 / 目标 / 奖励在格子里显示摘要（`EnterZone - 进入某场景时`、`10001 | 任务目标1`、中文原文），
  点一下在弹层里编辑，关掉弹层表格立即刷新摘要。
- **列是按记录类型的字段反射生成的**：数据类加个字段，表格自动多一列，不用改编辑器。
- 列宽拖完记在 `EditorPrefs`（按页签 ＋ 列名），下次开窗还是这个宽度。

- 结构 `QuestEditorWindow.uxml`，样式 `QuestEditorWindow.uss`（沿用原来的视觉），C# 只做数据绑定。
- **整个窗口不碰 `SerializedProperty`**：数据是 Odin 序列化的普通 C# 对象（字典 ＋ 多态实例），
  `QuestEditorFields` 按反射直接读写字段，改完 `SetDirty`。
- Odin 在这套里只负责一件事：`SerializedScriptableObject` 把字典和多态实例存进资产。其余全是项目自己的代码。

## 字段是怎么画出来的

`QuestEditorFields` 按字段类型和任务系统自己的几个特性（`QuestAttributes.cs`）决定控件：

| 字段 | 弹层里的控件 |
| --- | --- |
| `[QuestRef(...)] long` | 候选 ≤200 条（任务 / 目标 / 条件 / NPC / 场景）是一行下拉框；道具这种上千条换成搜索框，候选平时收着 |
| `[QuestLabel("持有数量")] int` + `[QuestMin(1)]` | 整数框，输入时钳下限 |
| `LocKeyRef`（多语言字段） | 多语言 Key 选择器：当前 Key ＋ 中文预览，候选可搜索、8 条一页；只为它开的弹层里直接展开，嵌在别的字段里默认收起 |
| `AssetReferenceSprite` | Sprite 拖拽框，存 GUID |
| 枚举 / bool / string | EnumField / Toggle / TextField |
| 抽象类、接口字段（`QuestObjData`、`IQuestTrigger`、`IQuestReward`） | 类型下拉 ＋ 展开该类型自己的字段 |
| `List<ID / 数值>` | 一项一行 ＋ 上移下移删除 |
| `List<多态 / 结构体>` | 每项一张卡（多态项带类型下拉）＋ 上移下移删除 |

所以**加一种目标 / 触发 / 奖励，编辑器一行都不用改**：写个子类，`[QuestTypeInfo("一句中文说明")]` 标上，
类型下拉里就有了。下拉和表格摘要统一显示「枚举名 - 中文说明」（`EnterZone - 进入某场景时`）：
枚举名取实现类的 `Type` 属性，目标没有这个属性就用类名去掉 `ObjData` 后缀（结果和 `QuestObjType` 一致）。
字段加 `[QuestLabel]` 就有中文名。

ID 选择器的数据：道具 / NPC / 对话 / 场景来自 Luban 导出的 JSON（`Assets/AddressableAssets/Remote/Configs/LubanJson`），
任务 / 目标 / 条件来自资产自己，都在 `QuestRefCatalog`（编辑器）。JSON 重导后点一次「保存」会清缓存，或重开窗口。

## 校验分两处

| 什么时候 | 查什么 | 在哪 |
| --- | --- | --- |
| 点工具栏「校验」 | 结构：漏选类型、引用的任务/目标/条件不存在、缺描述、缺奖励显示 | `QuestConfigValidator.CheckStructure` |
| 进游戏启动时 | 存在性：道具/角色/任务 ID 在各自表里有没有、数值是不是正数 | `QuestConfigValidator.ValidateAll` |

道具和角色要问运行时管理器，所以那部分只能进游戏才查 —— Console 里会打出是哪个任务哪一条。

## 多语言 Key 前缀约定

任务 `Quest/`、目标（含超额）`QuestObj/`、类别 `QuestCategory/`、奖励显示名 `QuestRewardName/`，
表是 `LocTableSet.QuestSystem`。Key 选择器按记录类型只列对应前缀的 Key，导入时也会自动补前缀。

## 一次性导入怎么用

菜单里那一项用 5 张 Luban Excel **覆盖**整个资产（`QuestCategoryData` / `QuestDataConfig` /
`QuestObjConfig` / `QuestRewardData` / `QuestStoryCondData`），直接读 `.xlsx` 的 OpenXML，不依赖 Excel 客户端。
旧的位置参数字符串（`HoldItem:100001:2`）在导入时被翻译成对应的实现类实例。

导完确认数据没问题之后，`QuestLubanMigration.cs` 连同这 5 张表就可以删了。

## 文件一览

| 文件 | 作用 |
| --- | --- |
| `QuestEditorWindow.cs` / `.uxml` / `.uss` | 窗口外壳：工具栏、页签、表格与列、弹层、五张表的增删改键 |
| `QuestEditorFields.cs` | 反射画字段与摘要：ID 选择器、多语言选择器、多态下拉、List 卡片 |
| `QuestEditorLoc.cs` | 多语言 Key 读取／预览、Sprite ↔ AssetReference 转换 |
| `QuestRefCatalog.cs` | ID 下拉的候选数据 |
| `QuestLubanMigration.cs` | 一次性 Excel 导入（可删） |
