任务系统策划需求

本文是策划原始需求的整理稿：只统一表述、补上参数含义、标注实现状态，不改需求本意。
原始条目的编号一律保留（领取方式原文跳过了 4、5，这里也不补），方便和策划的旧文档对照。
可配置的实际写法见同目录《任务配表说明.md》；程序侧设计见《任务系统规范.md》。

术语约定
- 领取方式：任务从「没出现」变成「已接取」的触发时机。和「领取条件」是两回事：条件是能不能领，方式是什么时候去问一次。
- 完成条件：接取后要达成的目标。一条任务可以有多条目标。
- 超额完成条件：主目标之外的附加目标，达成了额外发一份奖励。
- 「1 个或者多个」：一条配置只写一个对象；要多个就并列写多条，不是在一条里塞多个 ID。
- 状态：已实现 / 部分实现 / 未实现，指当前代码能不能配出来。


一、领取方式

| 编号 | 名称 | 参数 | 说明 | 状态 |
| --- | --- | --- | --- | --- |
| 1 | 进入区域 | 场景ID | 玩家进入该场景的瞬间 | 已实现 |
| 2 | 离开区域 | 场景ID | 玩家离开该场景的瞬间 | 已实现 |
| 3 | 区域内停留 | 场景ID + 秒数 | 进入该场景并连续停留够秒数；中途离开重新计时 | 已实现 |
| 6 | 点击 NPC | NPC ID | 点到该 NPC，不要求进对话 | 已实现 |
| 7 | 与 NPC 对话 | NPC ID | 和该 NPC 的对话结束时 | 已实现 |
| 8 | 小游戏开始 | 小游戏类型 | 开局瞬间 | 未实现（只做了结束/结果，需要就补） |
| 9 | 小游戏结束 | 小游戏类型 | 本局结算，不看胜负 | 已实现 |
| 10 | 小游戏结果 | 小游戏类型 + 胜/负 | 本局结算且结果匹配 | 已实现 |
| 11 | 另一个任务的进度 | 任务ID + 时机（接取／完成） | 别的任务被接取或交付时 | 部分实现（「完成」走接受条件的前置任务列；「接取」这个时机没做） |
| 12 | NPC 数值达标 | NPC ID + 数值类型 + 数值 | 该 NPC 的某项数值达到阈值，走接受条件的 NPC 数值列 | 部分实现（见下方「数值类型」一条） |
| 13 | 剧情播完 | 剧情ID | 某段剧情结束时 | 未实现（剧情只记录到单条对话，没有「剧情ID 已完成」的概念） |
| 14 | 游戏时间到达 | 天数 + 时段(TimeSlot) | 到第 N 天的某个时段，走接受条件的天数/时段两列 | 已实现 |
| 15 | 随机 | 触发概率 | 每次重新检查时按概率命中 | 已实现（概率按千分比填，例：50 = 5%） |

数值类型（第 12 条）：原文列的「好感、压力、灵感、当前/最大体力、当前/最大行动力、金币」混了两种东西——
好感属于 NPC，压力/灵感/体力/行动力/金币属于玩家自己。现在能按 NPC 配的只有好感值、心情值、好感等级；
玩家自己的资源要做成条件是另一套（玩家资源条件），目前没有。

另外，第 8、9、10 条里的「游戏」都指小游戏，参数不是随手写的数字 ID，而是程序登记好的小游戏名
（见《任务配表说明.md》的小游戏类型一览）；没登记的小游戏统计不到，要加找程序补一项。


二、完成条件（任务目标）

| 编号 | 名称 | 参数 | 说明 | 状态 |
| --- | --- | --- | --- | --- |
| 1 | 度过游戏时长 | 天数 | 游戏进行到第 N 天 | 已实现（按天，界面上能看到 1/2 这样的进度） |
| 2 | 完成 N 局某小游戏 | 小游戏类型 + 局数 + 胜/负（可不填） | 不填胜负则不限；只统计接了任务之后的局 | 已实现 |
| 3 | 与指定 NPC 对话 | NPC ID + 次数 | 多个 NPC 就并列写多条 | 已实现 |
| 4 | 给指定 NPC 送礼 | NPC ID + 礼物ID + 次数 | 礼物ID 填 0 表示任意礼物 | 部分实现（指定某个礼物或任意礼物可以；「某一类礼物」没做） |
| 5 | 带着道具与 NPC 对话 | NPC ID + 道具ID + 次数 | 每达成一次消耗 1 个该道具；道具不够那次不算 | 已实现 |
| 6 | 购买道具 | 道具ID + 件数 | 道具ID 填 0 表示任意道具 | 已实现 |
| 7 | 完成其它任务 | 任务ID | 多个任务就并列写多条 | 已实现 |
| 8 | 持有指定道具 | 道具ID + 数量 | 看当前背包里有几个，卖掉会掉回去（完成之前） | 已实现 |
| 9 | NPC 数值达标 | NPC ID + 数值类型 + 数值 | 数值类型的限制同第一部分第 12 条 | 部分实现 |

两点需要策划知道的判定规则：
- 第 1、8、9 条看的是「当前状态」，所以接任务时就已经满足的话，一接就直接完成、直接发奖。
  要求玩家接了任务之后再去做，就把任务的「目标按顺序完成」打开。
- 第 2、3、4、5、6 条是「接任务之后开始数次数」，接之前做过的不算，进度也只增不减。


三、超额完成条件

写法和完成条件完全一样，可用的类型也一样，额外多一条：

| 编号 | 名称 | 参数 | 说明 | 状态 |
| --- | --- | --- | --- | --- |
| 1 | 完成剧情 | 剧情ID | 某段剧情播完 | 未实现（同第一部分第 13 条；退一步可以按「完成某段对话」配） |
| 2~9 | 同「二、完成条件」第 2~9 条 | 同上 | 同上 | 同上 |

结算时机：超额只在**主目标完成的那一刻**判定一次——那一刻超额也满足才发超额奖，之后再补做不算。
所以配超额时要保证它能在主目标完成之前或同时达成。
